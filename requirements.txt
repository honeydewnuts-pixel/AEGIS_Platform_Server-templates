# fastapi/starlette note (fixed after a real pip-audit CI failure):
# FastAPI does NOT pin an upper bound on starlette - its own metadata
# only requires starlette>=0.46.0, so bumping fastapi alone does not
# guarantee a patched starlette. The line below pins starlette
# explicitly, above every CVE pip-audit found in 0.48.0 (host header
# injection enabling auth bypass, path-based SSRF, a Range-header ReDoS,
# and an HTTPEndpoint method-dispatch issue - fixed across versions up
# to 1.3.1). fastapi is bumped to a version built for the lifespan API
# (main.py no longer uses @app.on_event, which Starlette 1.0+ removed).
#
# Second pip-audit pass (this fix) - five more packages had drifted
# behind real, current CVEs since they were first pinned: path
# traversal + several DoS issues in python-multipart, a long list of
# decompression-bomb/heap-overflow issues in pillow (font/PDF/TGA/JPEG2000
# parsing paths), a symlink-following file-overwrite issue in
# python-dotenv, a .netrc credential leak in requests, and several
# certificate-validation and a Bleichenbacher-oracle issue in
# cryptography. None of these require a code change on this project's
# side - confirmed none of the fixed CVEs touch the specific APIs this
# codebase actually uses (e.g. cryptography's AESGCM class, used in
# credential_vault_service.py, is untouched by any of them).
